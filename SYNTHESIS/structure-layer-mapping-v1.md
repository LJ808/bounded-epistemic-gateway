# Structure Layer — What This Project Already Does, Named Correctly

## Why this file exists

FLF asked for three steps in this kind of project, not two. They call the three steps "ingestion, structure, and assessment." [[two-layer-architecture-v1]] only names two of those steps: rewrite (ingestion), then check (assessment). No file in this project names the third step, "structure," directly. But real work that fits "structure" already happens across this project. This file names that work honestly, without claiming more than what actually exists.

## What FLF means by "structure"

FLF names four things a good "structure" step should do:

1. Show which claims and evidence support which other claims.
2. Show where different sources answer different parts of a bigger question.
3. Notice when two claims say almost the same thing in different words.
4. Track how all of this changes as new claims and evidence arrive.

## Where this project already does that work

**Links between claim files.** Each of the eight claim files carries a section called "Related Claims." [[two-layer-architecture-v1]] states plainly that this section sits outside both the rewrite step and the check step — it counts as separate, connecting work. These links already do real "structure" work: they show which claim supports another, argues against another, or names a key open question the two claims share. No file called this "structure" work before now.

**[[crux-analysis-v1]].** This file ranks the open questions that matter most across all eight claims. This matches FLF's first "structure" goal exactly: showing which claims and evidence actually drive the conclusion, and which questions would change the most if answered.

**[[literature-engagement-addendum-v1]] and [[literature-engagement-addendum-v2]].** These two files track how our thinking changed as new outside papers came in. That fits FLF's fourth "structure" goal directly. We wrote them as responses to new evidence, though. We never labeled them as "structure" work until this file.

## What this project doesn't do yet

No single file lays out, in a clear and checkable way, exactly which claim supports which other claim and how. The rewrite step produces one clear output: a rewritten sentence. The check step produces three clear outputs: what got hidden, what stays unclear, and how someone could misuse the claim. The "structure" work in this project, by contrast, lives only inside links between files. Real, but informal. No fixed format. A judge can't open one file and see a clean, structured map of "claim A supports claim B, for this reason." They can open a claim file and see the rewrite/check split clearly, though.

We also haven't built anything that catches two claims saying almost the same thing in different words — FLF's third "structure" goal. Nothing in this project's eight claims does that work yet.

## Where this stands, honestly

This file names real work this project already does — work that fits FLF's "structure" step, but that no file named as such before now. It also states plainly what still needs building: a real, checkable "structure" output, built with the same care [[two-layer-architecture-v1]] gave the check step, plus a way to catch near-duplicate claims. Building that properly counts as future work. This file closes the naming gap today. It doesn't close the building gap.

**Update, 2026-07-17:** the building gap now has a first real answer. [[structure-layer-worked-example-v1]] builds the actual structured output this file said didn't exist -- a fixed vocabulary (supports / argues_against / shares_open_question_with, joined by a fourth tag, combines_with, added later the same day), applied across all three cases, all twenty-one within-case pairs. Extended same session from an initial eggs-only pass to cover covid-origins and black-holes too, on direct request, then again same day to cover [[covid-005]] and [[covid-006]]. Cross-case pairs (eggs against covid, etc.) still untested; near-duplicate detection now exists and runs clean across all twelve claims.
